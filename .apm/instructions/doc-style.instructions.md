# 生成する Markdown 文書のスタイル規約

エージェントが生成・更新するすべての Markdown 文書に適用する。目的は、一画面に表示される情報を適度に密に保ち、ユーザーの把握とレビューをやりやすくすること。

- セクション(見出し)は多用しない。見出しはスタイルの都合上、文書を縦に間延びさせるため、文書全体の大きな区切りにのみ最小限使う。
- 論理の多段構造(分解、階層、依存関係)は、見出しの階層や地の文ではなく、箇条書きとサブアイテムのネストで表現する。
  - 1項目1論点にする。1つの項目に複数の主張を詰め込まない。
  - ネストは意味のある階層にのみ使う。深くなりすぎる場合は表への変換や文書分割を検討する。
- 並列した情報(選択肢比較、トリアージ、リスク一覧、ID台帳など、同じ属性を持つ項目の並び)は表を効果的に多用し、レビューしやすくする。
  - 表の列は比較・レビューに使う観点で設計する。セル内の長文は避け、詳細はリンクで逃がす。
  - 複数項目の並列比較を地の文や箇条書きの羅列で書かない。表にする。
- 装飾目的の空行・水平線・冗長な前置きを入れず、情報密度を保つ。
- 改訂の経緯・判断時のメタ情報を前提とする文言を文書に残さない(例:「フィードバックを受けて X はスコープ外になった」)。文書は改訂の経緯・流れを知らない第三者にクリーンに読めなければならない。

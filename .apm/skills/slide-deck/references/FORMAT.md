# スライド標準フォーマット仕様 v1

HTML製スライドの標準フォーマット。slide-deck の `assets/new.html` がこの仕様の実装でありテンプレートでもある（1ファイル完結・依存なし）。
編集と発表は slide-editor が担う。この文書は**原稿の書き方**だけを定める。

---

## 1. 基本方針

| 項目 | 決定 |
|---|---|
| 用紙 | 16:9 固定 / 論理サイズ 1280 × 720 px |
| 出力 | 閲覧用HTML 1枚（意匠層＋束ね層＋原稿をインライン）＋ ブラウザ印刷でPDF |
| 編集 | 成果物には編集機能を入れない。ブラウザ上での編集は slide-editor が取り込んで行う |
| 依存 | なし。CDNも使わない（オフライン・共有フォルダで開ける） |
| テーマ | light / dark / auto。CSS変数で全色を一元管理 |
| マスター | report / jtc / mono の3種。構造を変えずに意匠だけ差し替える |
| 動き | スライド自体は静的。動くのは `embed` で載せた可視化アプリだけ |
| 真実のソース | DOM。`<section class="slide">` の中身がそのままコンテンツ |

中間データ形式（JSON等）を持たない。HTMLを直接手で直しても壊れない。

閲覧用HTMLは 3 つの部品でできている。`<style id="deck-style">` が意匠層（マスター一式）、
`<div class="dm-deck" id="dmDeck">` が原稿、`<script id="deck-layout">` が束ね層（並べる・採番・縮小）。
**書き換えてよいのは原稿と、`<html>` のマスター・テーマ属性、`<title>` だけ。**

## 2. デザイントークン

もとになったドキュメント型資料の配色をそのまま継承する。

```
--bg          #f6f5f2   地色（温かみのあるオフホワイト）
--surface     #ffffff   カード面
--surface-2   #fbfaf8   テーブルヘッダ等の一段沈めた面
--ink         #15181c   本文
--ink-2       #3a4047   副次テキスト
--muted       #656c75   ラベル・注記
--line        #e3e0d9   罫線
--accent      #14549b   アクセント（青）
--warn        #4a6580   保留・要検討（落ち着いた青）
--alarm       #b03a39   注意・否定（赤）
```

各色に `-soft`（背景用）と `-line`（枠線用）の派生を持つ。
dark テーマでは同名の変数を差し替えるだけで、コンポーネント側のCSSは共通。

### 配色

**色は青に集約する。** 見出し・罫・表ヘッダ・肯定（`.ok`）はアクセントの青、
保留や要検討（`.mid`）は落ち着いた青、と青の濃淡で段階を表す。

**赤だけは別扱い**で、はっきり否定・警告したいとき（`.ng`、`alarm`）にのみ使う。
赤が効くのは、ほかが青で揃っているからなので、多用しない。

緑・褐色・黄といった第三の色相は使わない（工程表の重点バーも淡い青）。
`mono` マスターだけは例外で、黒＋朱の2色で構成する。

### 情報密度

**1枚にできるだけ情報をまとめ、枚数を嵩張らせない**ことを優先する。

そのため既定の余白は詰めてある（カラム間16px、カード間8px、ブロック間12px）。
**左端だけ太い罫を引く表現は使わない** — Webアプリのアラートの作法であって、
スライドのそれではない。箱は全辺とも同じ太さの細罫にする。

### 箱の描き方

**箱は白地・ほぼ直角・1pxの細い罫・影なし**を既定とする。
`note` / `warn` / `key` の意味の違いは、淡色のベタ塗りではなく
**左端の3px罫と見出しの色**で示す。色は罫と文字にだけ使い、面には置かない。

### 組版

- 和文: `Hiragino Sans` → `Noto Sans JP` → `Yu Gothic Medium` → `Meiryo`
- `font-feature-settings: "palt" 1`（和文プロポーショナル詰め）
- 等幅: `SFMono-Regular` → `Menlo` → `Consolas`
- スライド基準 20px / 行間 1.7。ドキュメントの15pxから投影用に拡大

### 間隔

8px グリッド。スライド余白は上下 60px / 左右 82px。

## 2.5 スライドマスター（`data-master`）

`<html data-master="…">` で3種から選ぶ。ツールバーの「マスター」ボタン、または
属性を直接書き換える。選んだマスターはファイルに保存され、印刷にも引き継がれる。

| 値 | 用途 | 意匠 |
|---|---|---|
| `report` | **標準（既定）** | 余白を広めに取り、文章主体で読ませる資料向け |
| `jtc` | 1枚に詰めたいとき | 白地＋濃紺 `#1f4e79`。文字・余白・表・カードをひとまわり詰め、本文は 18.5px（14pt 相当）。3カラムでも破綻しない。**メッセージライン**と**脚注**が使える |
| `mono` | 投影・白黒印刷 | 黒＋朱 `#c2342a` の1色。罫のみ、角丸ゼロ、コールアウトは箱をやめて左罫。白黒コピーでも情報が落ちない |

マスターが差し替えるのは**トークンと造作だけ**で、HTMLの構造は共通。
同じ原稿を3種類の見た目で出せる。

```
色トークン一式 ／ --r-s --r-m --r-l（角丸） ／ --pad-x --pad-y（版面余白）
--fs（本文の基準サイズ。書体差の吸収） ／ --title-c（見出しの色） ／ --font-ja
```

表紙・章扉・主張スライドの反転は、その要素の上でトークンを再定義して
中身を一括で追随させている（個別に色を指定していない）。
ただし**背景色そのものは実色で書く**。同じ規則の中で `--accent` を再定義すると
`background: var(--accent)` が新しい値で解決され、地と文字が同色になって白飛びする。

### 章タブ（`.s-tabs`）

スライドの先頭に置くと、上端に進行タブが出る。

```html
<div class="s-tabs" data-block="tabs"><i>第1部</i><i class="on">第2部</i><i>第3部</i></div>
```

既定ではシェブロン形、`mono` では角の立った枠線になる。
タブを置いたスライドでは、左上の走りラベル（`data-chapter`）は自動で消える。

### メッセージライン（`.s-msg`）と脚注（`.s-note`）

情報量の多いスライドで効く2つ。どのマスターでも使えるが、`jtc` で本領を発揮する。

```html
<h2 class="s-title">…</h2>
<div class="s-rule"></div>
<div class="s-msg" data-block="msg">このスライドの主張を1行で。</div>
<div class="s-main"> … </div>
<div class="s-note" data-block="note-foot"><b>出典</b> …　<b>※</b> …</div>
```

`.s-msg` はタイトル直下、`.s-note` は `margin-top: auto` で版面の下端に寄る。
どちらも `.s-main` の外側に置く。順序は タイトル → 罫 → メッセージライン → 本文 → 脚注。

### ロゴ枠（`.s-logo`）

どのマスターでも使える。スライドの先頭に置くと右上に出る。
空のときは破線の枠が見えるので、そこへ画像をドラッグすると data URL で埋め込まれる。

```html
<div class="s-logo" data-block="logo"><img src="data:image/png;base64,…" alt=""></div>
```

会社のロゴは**同梱していない**。各自で用意して入れる。

### マスターを変えると版面は動く

書体も基準サイズも変わるため、あるマスターで収まっていた原稿が別のマスターで
あふれることがある。`jtc` は余白と行間を詰めるぶん1枚に載る量が多いので、**`jtc` 前提で書いた原稿は
他のマスターではまず収まらない**。1つの原稿を複数マスターで回すつもりなら、
いちばん緩いマスターに合わせて書く。確認は次のコマンドで行う。

```bash
python3 scripts/audit-overflow.py <閲覧用HTML>
```

ヘッドレスブラウザで開いて実測し、マスターごとにはみ出したスライドと px を出す。
はみ出しが 1 件でもあれば終了コードが 1 になる。

## 3. スライドレイアウト（`data-layout`）

`<section class="slide" data-layout="...">` で指定する。8種。

| 値 | 用途 | 構造 |
|---|---|---|
| `cover` | 表紙 | kicker / タイトル / リード文 / 出典 |
| `agenda` | 目次 | 番号付き項目を2カラム |
| `section` | 章扉 | 大きな章番号 + 章タイトル + 一行説明 |
| `body` | 標準 | スライドタイトル + 罫 + ブロック自由配置（1カラム） |
| `split` | 2カラム | タイトル + 左右ペイン。左に論、右に図表 |
| `visual` | 図表全面 | タイトル細め + 図表を最大化 |
| `statement` | 主張1枚 | 大きな一文。章の結論・転換点に使う |
| `closing` | 締め | 次アクション / 確認事項 |

共通クロム（`cover`/`statement` を除く）:
- 左上に走り書きラベル（章名）
- 右下にページ番号 `n / N`（自動採番）

## 4. コンテンツブロック（`data-block`）

スライド本文に置ける部品。すべて `<div data-block="...">`。
slide-editor の挿入メニューもこの一覧に対応する。

| 値 | 部品 | 出所 |
|---|---|---|
| `heading` | 小見出し | `h3` |
| `text` | 段落 | `p` |
| `list` | 箇条書き / 番号付き | `ul` / `ol` |
| `note` | 補足ボックス（緑） | `.note` |
| `warn` | 注意ボックス（褐） | `.warnbox` |
| `key` | 要点ボックス（白・影） | `.keybox` |
| `table` | データテーブル | `.tw > table` |
| `steps` | 手順・プロセス | `.steps > .step` |
| `cards` | カード並べ | `.parts` |
| `kpi` | 数値の強調（大きな数字＋単位＋注） | 新規 |
| `qa` | Q&A | `.qa` |
| `figure` | 図（インラインSVG / 画像 / 埋め込み） | `figure > .figbox` |
| `code` | コード | `pre > code` |
| `quote` | 引用 | 新規 |
| `cols` | 2カラムの入れ物（中に他のブロックを入れる） | `.s-cols > .s-col` |
| `flow` | 横に並ぶ工程と矢印 | 新規 |
| `bars` | 横棒の比較（周期・規模・割合） | 新規 |
| `stack` | 層の積み重ね（所与の層と、決める層） | 新規 |
| `chain` | 日をまたぐ鎖（前日の終着＝翌日の始発） | 新規 |
| `roadmap` | 年度×ワークストリームの工程表（ガントの簡略形） | 新規 |
| `embed` | 既存の自己完結HTMLアプリをそのまま載せる | 新規 |
| `spacer` | 余白調整 | 新規 |

### インライン装飾

| 記法 | 意味 |
|---|---|
| `<strong>` | 強調 |
| `<span class="ok">` | 良好・達成（accent色） |
| `<span class="mid">` | 注意・要検討（warn色） |
| `<span class="ng">` | 未達・不可（alarm色） |
| `<code>` | ファイル名・識別子 |
| `.num-cell` | 数値セル（`tabular-nums` + 右寄せ + 折返し禁止） |

## 4.4 工程表（`roadmap`）

年度 × ワークストリームの工程表。**横位置はピクセルでも日付でもなく「列番号」**で決める。
CSS Grid の列に載せているだけなので、あとから列を足しても全体が破綻しない。

```html
<div class="rm" style="--cols: 24; --lw: 74px;">
  <div class="rm-row"><div class="rm-lab"></div><div class="rm-track">
    <div class="rm-y" style="--a:1; --b:5">FY2025</div>          <!-- 年度ヘッダ -->
  </div></div>
  <div class="rm-row"><div class="rm-lab">マイルストン</div><div class="rm-track">
    <div class="rm-m" data-tone="key" style="--a:10; --w:3"><b>意思決定</b><i>2026.9</i></div>
  </div></div>
  <div class="rm-sec"><div class="rm-lab rm-lab--v">全体像</div><div class="rm-sec-body">
    <div class="rm-row"><div class="rm-track">
      <div class="rm-bar" data-tone="hi" style="--a:1; --b:6"><span><b>検討</b><i>補足</i></span></div>
    </div></div>
  </div></div>
</div>
```

| 変数・属性 | 意味 |
|---|---|
| `--cols` | 総列数。`.rm` に書く |
| `--lw` | 左ラベル列の幅 |
| `--a` / `--b` | 開始列 / 終了列（**その手前まで**。CSS Grid の流儀） |
| `--w` | マイルストンの横幅（列数、既定3） |
| `data-tone` | `hi` 重点（黄）／なし 確定（白地＋枠）／`plan` 未確定（破線）／`fill` 濃色ベタ／`open` 矢じりなしの箱 |
| `data-tone="key"` | マイルストンを赤で強調。1枚に1つだけ |

`.rm-sec-body` の中の `.rm-row` はラベル列を持たない。3階層にしたいときは
`.rm-sec` を入れ子にする。バーの中身は `<span><b>主題</b><i>補足</i></span>`。

破線（`plan`）だけはクリップパスで矢じりを描けないため、矩形＋回転した角で
矢じりを作っている。他のトーンは二層のクリップパスで枠つきシェブロンにしている。

## 4.5 既存の可視化を埋め込む

`embed` ブロックは、別に作った**自己完結HTMLのミニアプリを、中のJSに一切触らずに**
スライドへ載せるための枠。`srcdoc` に入れるだけで、クリック操作もそのまま効く。

```html
<div class="embed" data-ew="1220">
  <iframe title="…" srcdoc="&lt;!doctype html&gt;…"></iframe>
</div>
```

| 属性 | 意味 |
|---|---|
| `data-ew` | 中のアプリに使わせる論理幅（px）。この幅でレイアウトさせる |
| `data-eh` | 論理高さ。**省略すると中身の高さを実測する**（推奨） |

読み込み後・スライド切り替え時・リサイズ時に枠の実寸を測り、`transform: scale()` で
収める。スライドは表示中のものしか描画されないため、**切り替わった時点で測り直す**。

見た目だけスライド用に詰めたいときは、`srcdoc` の `</head>` 直前に
`<style>` を1つ足すのが定石（JSには触らない）。

## 5. 調整ノブ（属性・CSS変数）

構造を変えずに見た目を振れる範囲。すべて任意。

| 対象 | 指定 | 効果 |
|---|---|---|
| スライド | `data-chapter="01 相談の中身"` | 左上の走りラベル |
| スライド | `data-density="tight"` | 文字と余白を一段詰める（情報量の多い回） |
| スライド | `data-nochrome` | 走りラベルとページ番号を消す |
| `.s-cols` | `style="--split: 1fr 1.15fr"` | 2カラムの配分 |
| `.cards` / `.kpis` | `style="--n: 4"` | 横に並べる数 |
| `.kpi` | `data-tone="warn" \| "alarm" \| "plain"` | 数値の色 |
| `table` | `class="compact"` | 行を詰めた表 |

ページ番号（`data-page` / `data-total`）は読み込み時に自動採番されるので、手で書かない。

## 6. 版面の確認

スライドは 1280×720 で `overflow: hidden`。**はみ出しても画面上は静かに切れる**ので、書いたら必ず測る。

```bash
python3 scripts/audit-overflow.py slides/<name>/<name>.html
```

マスターを指定すると、その分だけ測る（既定は report / jtc / mono の 3 種）。はみ出したら、文章を締める →
`data-density="tight"` を足す → それでも収まらなければスライドを分ける。文字を小さくして詰め込むのは最後の手段。

## 7. 印刷とPDF

ブラウザの印刷で PDF にする。`@page` は 13.333in × 7.5in 横（PowerPoint 16:9 と同寸）で、1 スライド = 1 ページ。
印刷時はテーマをライトに固定する（束ね層が `beforeprint` で切り替える）。
